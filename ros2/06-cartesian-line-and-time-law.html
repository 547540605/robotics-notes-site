ROS 2 全景看板 · ROS2-05：连续选支 · 04–13 路线

ROS 2 工程实战 06：笛卡尔直线与五次时间律

把“从 A 到 B”变成连续目标点列。机械臂的关节角通常不是直线，但末端在 base_link 中必须是直线。

工程痛点：关节平滑，不代表末端走直线

即使让 joint1, joint2, joint3 各自做漂亮的三次或正弦曲线，机械臂末端 tool0 在三维空间中仍会走出弯曲弧线。若任务要求沿边缘靠近、沿直线插入或避开固定区域，路径必须先在笛卡尔空间（base_link 三维坐标）按直线生成每一时刻的末端目标点，再逐点经 IK 变成关节角。

① 定起点 A、终点 B同一 base_link 三维坐标
② 算路程比例 s(t)0→1 走完全程的几成
③ 算末端目标点 P(t)时刻 t 的 (x, y, z) 坐标
④ 逐帧连续 IK由 P(t) 解出关节角 q(t)
⑤ 发布显示驱动 RViz 数字孪生
本篇边界：仍然只驱动 RViz 数字孪生。发布到 /joint_states 是显示状态，不是执行器命令；真实控制器的 JointTrajectory 在 ROS2-13 再接入。

1. 先对齐所有符号与变量含义，再写直线公式

在看任何公式前，先把本篇出现的每一个符号代表什么物理对象、在哪个坐标系、是什么维度和单位彻底定死：

符号物理含义（到底是谁？）类型 / 维度所属坐标系与单位
\(\boldsymbol{A} = (x_A, y_A, z_A)\)直线起点：机械臂末端 tool0 出发时刻的目标坐标（固定常数，本例取 \((0.50, 0.00, 0.65)\)）三维位置向量 \(\mathbb{R}^3\)base_link，单位 \(\text{m}\)

\(\boldsymbol{v}(t),\ \boldsymbol{a}(t)\)时刻 \(t\) 末端 tool0 的期望线速度与线加速度：\(\boldsymbol{v}(t)=\dfrac{d\boldsymbol{P}}{dt}\)，\(\boldsymbol{a}(t)=\dfrac{d^2\boldsymbol{P}}{dt^2}\)三维向量函数 \(\mathbb{R}^3\)base_link，单位 \(\text{m/s}\)、\(\text{m/s}^2\)
\(\boldsymbol{q}(t) = (q_1(t), q_2(t), q_3(t))\)时刻 \(t\) 的关节角向量：把 \(\boldsymbol{P}(t)\) 交给 IK 与连续选支后解出的三轴关节角；\(\boldsymbol{q}_A, \boldsymbol{q}_B\) 分别代表起点 \(\boldsymbol{A}\)、终点 \(\boldsymbol{B}\) 对应的关节角三轴角度向量 \(\mathbb{R}^3\)关节空间，单位 \(\text{rad}\)

三维参数化直线方程

有了上面的定义，想求时刻 \(t\) 末端 tool0 的期望坐标 \(\boldsymbol{P}(t)\)，只需从起点 \(\boldsymbol{A}\) 出发，加上全程总位移向量 \((\boldsymbol{B} - \boldsymbol{A})\) 的 \(s(t)\) 倍（按 \(x, y, z\) 三个坐标分量展开就是右边的三条式子）：

\[\boldsymbol{P}(t) = \boldsymbol{A} + s(t)(\boldsymbol{B} - \boldsymbol{A}) \quad\Longleftrightarrow\quad \begin{cases} x(t) = x_A + s(t)(x_B - x_A) \\ y(t) = y_A + s(t)(y_B - y_A) \\ z(t) = z_A + s(t)(z_B - z_A) \end{cases}\]

为什么这一定是一条三维直线？因为 \(x(t), y(t), z(t)\) 三个坐标共用同一个标量比例 \(s(t)\)：当 \(x\) 走完全程增量的 \(30\%\) 时，\(y\) 和 \(z\) 也严格走完全程增量的 \(30\%\)，三轴增量始终成固定比例，因此点 \(\boldsymbol{P}(t)\) 永远落在连接 \(\boldsymbol{A}\) 与 \(\boldsymbol{B}\) 的三维直线段上。至于是哪一时刻 \(t\) 走到哪个比例 \(s(t)\)，由第 2 节的时间律决定。

不要做：关节空间直线插值

如果先求起点、终点的关节角 \(\boldsymbol{q}_A, \boldsymbol{q}_B\)，再按 \(\boldsymbol{q}(t) = \boldsymbol{q}_A + s(t)(\boldsymbol{q}_B - \boldsymbol{q}_A)\) 让三个关节角按比例变化，只能保证“关节角数值变化是线性的”；经过含有 \(\sin/\cos\) 的正运动学 FK 后，末端 tool0 在三维空间里走的是一条弯曲弧线。

本篇要做：笛卡尔空间直线 + 逐点 IK

先在 base_link 下按直线公式算出每一帧的末端三维坐标 \(\boldsymbol{P}(t) = (x(t), y(t), z(t))\)，再把每一个 \(\boldsymbol{P}(t)\) 交给 ROS2-04/05 的 IK 反解出 \(\boldsymbol{q}(t)\)。此时关节角曲线 \(\boldsymbol{q}(t)\) 是弯曲的，但末端 tool0 在三维空间走出的是真直线。

先拿同一组坐标走一遍：A → B

本篇始终使用 base_link 下的 A=(0.50, 0.00, 0.65) m、B=(0.40, 0.30, 0.75) m，总时长 T=3 s。先按坐标逐项相减，得到 B−A=(−0.10, +0.30, +0.10) m。这表示从 A 走到 B 时，x 减少 0.10 m、y 增加 0.30 m、z 增加 0.10 m；它不是关节角的变化量。

若此刻路径进度 s=0.5，三个坐标同时走完各自差值的一半：P=A+0.5(B−A)=(0.45, 0.15, 0.70) m。注意同一个 0.5 乘在 x、y、z 上，才保证这个点真的在三维直线上。

A、B 和 P 都是末端位置，不是三个关节角；P 只有经过 04 求 IK、05 按上一帧选支后，才会变成这一帧的 q=(q1,q2,q3)。

2. 为什么不用匀速突起突停？先分清谁是位置、速度、加速度

物理上速度的定义就是位置随时间的变化率 \(\boldsymbol{v}(t) = \dfrac{d\boldsymbol{P}}{dt}\)。因为这里的 \(\boldsymbol{A}\)、\(\boldsymbol{B}\) 和 \(\boldsymbol{P}(t)\) 都定义在地面固定的底座坐标系 base_link 下（坐标轴本身不随时间旋转），所以求末端线速度就是直接对坐标 \(\boldsymbol{P}(t)\) 关于时间 \(t\) 求导。

① 为什么“对 P(t) 求导”会变成“对 s(t) 求导”？

它们不是求了两次不同的导，而是同一个等式的左边和右边！把 \(\boldsymbol{P}(t) = \boldsymbol{A} + s(t)(\boldsymbol{B}-\boldsymbol{A})\) 代入求导：

  • 等号右边的起点 \(\boldsymbol{A} = (0.50, 0.00, 0.65)\) 是固定死数字，对 \(t\) 求导为 \(\boldsymbol{0}\)；
  • 总位移 \((\boldsymbol{B}-\boldsymbol{A}) = (-0.10, 0.30, 0.10)\) 也是固定死数字，求导时作为常数系数照抄；
  • 等号右边唯一随时间 \(t\) 变化的只有 \(s(t)\)！因此左边对 \(\boldsymbol{P}\) 求导，右边就归结为对 \(s\) 求导：
\[\boldsymbol{v}(t) = \frac{d\boldsymbol{P}}{dt} = \frac{ds}{dt}(\boldsymbol{B}-\boldsymbol{A})\] \[\boldsymbol{a}(t) = \frac{d^2\boldsymbol{P}}{dt^2} = \frac{d^2s}{dt^2}(\boldsymbol{B}-\boldsymbol{A})\]

拿 \(x\) 轴数字举例：\(x(t) = 0.50 + s(t)\times(-0.10)\)。求速度 \(v_x(t)=\dfrac{dx}{dt}\) 时，常数 \(0.50\) 求导没了，就变成 \(v_x(t) = \dfrac{ds}{dt}\times(-0.10)\)。所以不先把右边的 \(\dfrac{ds}{dt}\) 算出来，就拿不到具体的速度数值——左卡写出这层依赖关系，右卡接着代入具体的函数把导数算出来。

② 两种不同的“油门方案”：淘汰匀速 s₁(t)，换用五次时间律 s(t)

关键前提：进度函数不是客观算出来的唯一答案，而是你作为工程师自己设计的“油门踩法”！从 \(A\) 走到 \(B\) 规定 \(T=3\text{ s}\) 走完，只要满足“第 \(0\) 秒在起点、第 \(3\) 秒到终点”，中间这 \(3\) 秒里怎么分配进度完全由你决定。就像开车走同一段路，下面不是把同一个式子变形改写，而是枪毙方案一 \(s_1(t)\)，改用方案二 \(s(t)\)：

❌ 方案一 \(s_1(t)\)（匀速时间律，直接作废）：假设“全程定速巡航、匀速硬跑”，则时间过了几分之几，路程就走几分之几： \[s_1(t) = \frac{t}{T}, \qquad \frac{ds_1}{dt} = \frac{1}{T}\] 导数等于常数 \(\dfrac{1}{T}\)，意味着第 \(0\) 秒启动瞬间速度必须从 \(0\) 直接跳到常数，终点又瞬间归零，电机受不了。因此方案一 \(s_1(t)\) 不及格，直接扔进垃圾桶不用了！

✅ 方案二 \(s(t)\)（五次时间律，实际采用）：既然匀速废了，我们重新设计一个新函数 \(s(t)\) 模拟老司机开车：“起步轻踩油门慢加速 \(\to\) 中段跑快点把时间抢回来 \(\to\) 终点前轻踩刹车慢停下”。为此列出 6 个硬指标（方程）：

  • 起止位置对：\(s(0)=0,\quad s(T)=1\)
  • 起止速度为 0：\(s'(0)=0,\quad s'(T)=0\)
  • 起止加速度为 0：\(s''(0)=0,\quad s''(T)=0\)

6 个方程正好解 6 个未知系数，设五次多项式 \(\sum_{k=0}^{5} a_k\left(\frac{t}{T}\right)^k\) 代入上面 6 个条件解方程组，唯一解出 \(a_0=a_1=a_2=0,\ a_3=10,\ a_4=-15,\ a_5=6\)，这才得到实际采用的 \(s(t)\)：

\[s(t) = 10\frac{t^3}{T^3} - 15\frac{t^4}{T^4} + 6\frac{t^5}{T^5}\]

（代码里为免连写三次除法，令 \(u = t/T\)，简写为 \(s(u) = 10u^3 - 15u^4 + 6u^5\)。）对 \(t^3, t^4, t^5\) 求一阶、二阶导数：

\[\frac{ds}{dt} = 30\frac{t^2}{T^3} - 60\frac{t^3}{T^4} + 30\frac{t^4}{T^5}\] \[\frac{d^2s}{dt^2} = 60\frac{t}{T^3} - 180\frac{t^2}{T^4} + 120\frac{t^3}{T^5}\]

验算两端：代入 \(t=0\)，两式全为 \(0\)；代入 \(t=T\)，一阶导分子 \(30-60+30=0\)，二阶导分子 \(60-180+120=0\)。起止瞬间末端速度 \(\boldsymbol{v}=\boldsymbol{0}\)、加速度 \(\boldsymbol{a}=\boldsymbol{0}\)！

五次时间律并不改变几何路径（空间里还是同一条直线），只决定沿这条直线“什么时候走到哪里、什么时候加速与减速”。这正是几何路径与时间参数化的区别。

把 3 秒拆成五个时刻：一步步看代码每一帧到底在算什么

在写代码时，每到一个时刻 \(t\)，程序其实只按顺序做下面 3 步最简单的算术（拿表里第 2 行 \(t = 0.75\text{ s}\) 举例）：

  1. 先算时间过了几成（\(u = t/T\)）：总时长 \(T = 3\text{ s}\)，在 \(t = 0.75\text{ s}\) 时，\(u = 0.75 / 3 = 0.25\)（时间过去了 \(25\%\)）。
  2. 再算路程该走几成（代入五次时间律求 \(s\)）：把 \(u = 0.25\) 代入 \(s = 10u^3 - 15u^4 + 6u^5\)，算出 \(s \approx 0.1035\)。因为刚起步还在慢加速，时间虽然过了 \(25\%\)，路程其实只走了 \(10.35\%\)。
  3. 最后算此刻的三维目标坐标 \(\boldsymbol{P}(t)\)：代入 \(\boldsymbol{P}(t) = \boldsymbol{A} + s(\boldsymbol{B}-\boldsymbol{A})\)，让总位移 \((-0.10, +0.30, +0.10)\text{ m}\) 乘上 \(0.1035\) 再加到起点 \(\boldsymbol{A}\) 上： \[\boldsymbol{P}(0.75) = (0.50, 0.00, 0.65) + 0.1035\times(-0.10, +0.30, +0.10) \approx (0.4896, 0.0311, 0.6604)\text{ m}\]

（表格顺带列出了导数 \(\dfrac{ds}{dt}\)，它的直观含义是“此刻每秒钟走完几个全程”——在 \(t=0\) 和 \(t=3\text{ s}\) 时它都是 \(0\)，在中间 \(t=1.5\text{ s}\) 时达到最大 \(0.625\)。）

工程追问：总时长 T（代码里的 duration）是怎么定出来的？为什么这里取 3 秒？

  • 在代码调用层：\(T\) 是你传给函数的输入参数 duration（想让它 \(3\text{ s}\) 走完就传 3.0，想慢一倍就传 6.0）。
  • 按末端最大允许线速度 \(v_{\max}\) 算（最常用）：因为五次时间律“两头慢、中间快”，它在中点 \(u=0.5\) 处的峰值速度正好是平均速度 \(\dfrac{L}{T}\) 的 \(1.875\) 倍（\(\frac{15}{8}=1.875\)）。若工艺规定末端最快不能超过 \(v_{\max}\)，则总时长必须满足： \[T \ge \frac{1.875\,L}{v_{\max}}\] 本例直线总长 \(L = |\boldsymbol{B}-\boldsymbol{A}| \approx 0.3317\text{ m}\)，若限制末端最高线速度不超过 \(v_{\max} \approx 0.21\text{ m/s}\)，代入得 \(T \ge \dfrac{1.875\times 0.3317}{0.21} \approx 2.96\text{ s}\)，向上取整就是本篇采用的 \(T = 3\text{ s}\)。
  • 按关节电机最高转速兜底：预扫描整段路径时，若发现某相邻两帧的关节角速度 \(\dfrac{|\Delta q_i|}{\Delta t}\) 超过了 URDF 的 velocity 上限（如 \(1.0\text{ rad/s}\)），就按超速比例把 \(T\) 拉长。

4. 动手写代码：把直线采样与 04/05 整段预扫描写进 cartesian_path.py

这一帧怎样接到 04、05？

仍看表里的 t=1.50 s：本篇先由 cartesian_line 算出 target=(0.45, 0.15, 0.70) m。接着：

  1. 把这个三维坐标传给 04 的 solve_position_ik(*target)，得到 reachable 与两支候选列表；
  2. 几何可达时，把候选列表和上一帧实际选用的关节角 q_prev 传给 05 的 select_nearest_valid_solution(candidates, q_prev)；
  3. 取出选中候选的 selected["q"] 作为本帧关节角 q_now，并用 04 的 forward_position(*q_now) 做 FK 回代核对位置误差，最后令 q_prev = q_now 进入下一帧。

如果中途任意一帧 04 报几何不可达，或 05 报无合法限位解，预扫描就立即在该帧停下并返回失败点信息（第几步、哪一秒、哪个坐标、什么原因），绝不跳过坏点继续执行。

第一步：新建 ~/ros2_ws/src/my_arm_motion/my_arm_motion/cartesian_path.py

在你已经建好的 my_arm_motion 包内层模块目录下新建 cartesian_path.py，写入以下完整代码（含五次时间律 quintic_s、直线点列生成器 cartesian_line 和整段预扫描函数 plan_cartesian_line）：

# 文件路径：~/ros2_ws/src/my_arm_motion/my_arm_motion/cartesian_path.py
import math
from my_arm_motion.kinematics_3r import (
    forward_position,
    solve_position_ik,
    select_nearest_valid_solution,
)


def quintic_s(u):
    """归一化时间进度 u∈[0,1] → 路程比例 s∈[0,1]；起止速度、加速度均为 0。"""
    if not (0.0 <= u <= 1.0):
        raise ValueError("u must be within [0, 1]")
    return 10.0 * u**3 - 15.0 * u**4 + 6.0 * u**5


def cartesian_line(start, end, duration, dt=0.02):
    """在同一 base_link 下按 dt(秒)采样 A→B 直线；每次 yield (t秒, (x,y,z)米)。

    这里只生成末端三维目标点，不求关节角；IK 与限位预扫描交给 plan_cartesian_line。
    """
    if duration <= 0 or dt <= 0 or len(start) != 3 or len(end) != 3:
        raise ValueError("need 3D endpoints and positive duration/dt")
    # 向上取整保证最后一次采样刚好落在 t = duration (终点 B)
    steps = math.ceil(duration / dt)
    for k in range(steps + 1):
        t = min(k * dt, duration)
        s = quintic_s(t / duration)
        target = tuple(a + s * (b - a) for a, b in zip(start, end))
        yield t, target


def plan_cartesian_line(start, end, duration, q_start, dt=0.02):
    """整段预扫描：将 A→B 直线点列逐帧经 04 IK 与 05 连续选支转换为关节角序列。

    输入：
      start, end : base_link 下起点 A、终点 B 坐标 (x, y, z)，单位 m
      duration   : 总时长 T，单位 s
      q_start    : 运动开始前机械臂所处的合法起始关节角 (q1, q2, q3)，单位 rad
      dt         : 采样步长，默认 0.02 s (50 Hz)
    返回字典：
      ok           : 整段所有采样点是否全部求解成功 (bool)
      trajectory   : 成功时为列表，每项含 {"t", "target", "q", "fk", "fk_error", "cost"}
      max_fk_error : 整段最大 FK 回代位置误差 (单位 m)
      failed_step  : 失败时记录第一处失败点的 {"step", "t", "target", "reason"}
    """
    q_prev = tuple(q_start)
    trajectory = []
    max_fk_error = 0.0

    for step_idx, (t, target) in enumerate(cartesian_line(start, end, duration, dt)):
        # 1) 调用 04 求当前目标点的双支几何 IK 候选
        ik_res = solve_position_ik(*target)
        if not ik_res["reachable"]:
            return {
                "ok": False,
                "trajectory": [],
                "max_fk_error": max_fk_error,
                "failed_step": {
                    "step": step_idx,
                    "t": t,
                    "target": target,
                    "reason": ik_res["reason"],
                },
            }

        # 2) 调用 05 筛三轴限位，并选出离上一帧 q_prev 最近的合法候选
        choice = select_nearest_valid_solution(ik_res["candidates"], q_prev)
        selected = choice["selected"]
        if selected is None:
            return {
                "ok": False,
                "trajectory": [],
                "max_fk_error": max_fk_error,
                "failed_step": {
                    "step": step_idx,
                    "t": t,
                    "target": target,
                    "reason": choice["reason"],
                },
            }

        # 3) 调用 04 的 FK 回代验算真实末端位置与目标点的误差
        q_now = selected["q"]
        fk_xyz = forward_position(*q_now)
        fk_err = math.dist(fk_xyz, target)
        max_fk_error = max(max_fk_error, fk_err)

        trajectory.append({
            "t": t,
            "target": target,
            "q": q_now,
            "fk": fk_xyz,
            "fk_error": fk_err,
            "cost": selected["cost"],
        })
        # 4) 将本帧选中的关节角作为下一帧的上一时刻基准 q_prev
        q_prev = q_now

    return {
        "ok": True,
        "trajectory": trajectory,
        "max_fk_error": max_fk_error,
        "failed_step": None,
    }

5. 运行前为什么必须做整段预扫描？

检查为什么不能省失败时正确处理
逐点 IKA、B 都有解不代表中间每一点都有解或在限位内。不启动该段；缩短路径、换姿态或重设目标。
连续选支每一帧独立求解会让双解随机切换。用 ROS2-05 的 q_prev 代价选择。
FK 位置误差目标点和实际关节 FK 必须对照。记录最大误差；异常时回查 IK/URDF 约定。
速度、加速度限值五次时间律不自动保证每个关节都不过速。先拉长 T；真实控制阶段再由控制器限速。
