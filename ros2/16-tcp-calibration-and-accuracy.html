ROS 2 工程实战 16：TCP、工位标定与精度误差预算

规划成功只说明模型中的 tool0 到了模型中的目标。要让真实工具真正对准工件，必须说清工具尖端在哪、工件坐标从哪来、每一段变换有多大误差。

本篇的中心问题：同一个“偏了 3 mm”，到底该怪谁？

world / cell→base_link→… 六轴关节链 …→flange→tool0 / TCP→workpiece target

TCP、工件坐标、底座安装、关节零位和载荷变形都会在这条链上留下误差。本篇的目标不是把所有误差“校到零”，而是让每个误差都有来源、测量方式、允许范围和复测规则。

先分清两种指标：重复精度是多次回到同一命令时彼此是否一致；绝对精度是实际 TCP 是否真的到达工件坐标的指定位置。一个机器人可以重复性很好、但整体偏了几毫米；前者好不代表后者好。

1. TCP 不是法兰中心，也不是 RViz 里的“最后一节 link”

三个常被混称为末端的点

  • flange：机械臂制造商定义的法兰连接面；
  • tool0：URDF/MoveIt 的工具参考 link，通常固定在法兰之后；
  • TCP：真正参与任务的点，例如吸盘中心、针尖、夹爪指尖中点、喷嘴出口。

当工具更换，法兰没变，TCP 往往已经变了。

姿态同样属于 TCP

TCP 不只是 xyz 偏移，还包含工具坐标轴方向。工具沿本地 +Z 插入、沿本地 +X 扫描、相机沿光轴观测，都会依赖这组轴。只标长度不标旋转，后续速度控制和视觉变换仍会错。

# 语义：固定变换 flange → tool0；数字必须来自图纸/测量/标定，而不是美观猜测。
<joint name="flange_to_tool0" type="fixed">
  <parent link="flange"/>
  <child link="tool0"/>
  <origin xyz="0 0 0.185" rpy="0 0 0"/>
</joint>

# MoveIt 的 Pose Goal 应落在 tool0；工艺点的方向也应按 tool0 的轴定义。

2. 真机 TCP 标定到底在解什么？

固定一个物理参考点 P，让工具尖端从多种明显不同的姿态都触到它。每次记录法兰相对 base 的位姿 T_base_flange(k)。未知的固定工具偏移 p_flange_tcp 应让以下各次计算出的 base 中点尽量重合：

P_base(k) = T_base_flange(k) · p_flange_tcp

# 理想情况：对所有 k，P_base(k) 相同。
# 实际情况：求一个 p_flange_tcp，使各 P_base(k) 的散布/残差最小。
# 若姿态变化太小，某些方向无法可靠辨识；不能只在同一姿态附近点几次。
现场限制：触碰工装、记录关节状态、更新真实 TCP 都涉及设备使能和人员/工装安全。无真机时只能理解方程、构造合成数据和检查 TF 链；不能声称已完成物理标定。

3. 工件坐标系：目标应该属于工件，不属于临时世界

推荐描述

在 workpiece_frame 下描述工艺点：例如孔位 (0.030, 0.015, 0)，法向为 +Z。工件搬到新夹具位置时，只更新 base_link → workpiece_frame，不必重写所有点位。

不推荐描述

把每个点直接写成 base_link 下的绝对坐标。工装移动 2 mm、底座重新安装或切换工位后，所有点都要人工改，且很难定位偏差来源。

T_base_tcp_target = T_base_workpiece · T_workpiece_tcp_target

# 左侧由标定/定位得到；右侧是工艺定义。
# 任何“没对准”都可以沿这两个变换分别检查，而不是混在一个 x/y/z 误差里。

4. 误差预算：先拆账，再决定校哪里

误差源现象怎样区分/测量优先修复方式
base 安装 / world→base所有点同方向整体偏移或旋转用多个固定基准点检查整体刚体残差重测安装位姿、更新 base 标定
TCP xyz / rpy换姿态后偏差方向/大小变化多姿态同点法；检查残差散布重做工具偏移与轴向标定
工件坐标同一工件的全部点一起偏测夹具基准、定位销、视觉/探针结果更新 workpiece_frame，不改工艺点
关节零位/连杆参数工作空间不同区域的误差模式不同多点、多姿态测量，拟合残差地图厂商/运动学参数标定，不能只调 TCP
载荷、挠度、温漂空载/负载、冷机/热机结果不同按载荷与时间分组复测负载模型、工艺限速、温度策略
测量基准本身每次测量不一致且无规律先估计量具/视觉重复性提升测量链，避免把噪声写入标定

5. 现在能学什么，真机到了再做什么

阶段可做事项不能声称完成的事项
现在在 URDF 中明确 flange→tool0；用 TF2 检查链；以合成误差演示“整体偏移”和“换姿态偏差”；建立误差记录表。真实 TCP 数值、真实绝对精度、负载/温漂影响。
真机 + 工装多姿态同点 TCP 标定；base/workpiece 基准测量；重复性与绝对误差采样；负载与热机对比。仅凭一次成功插入就宣称精度已验证。

6. 真机到位后的最小标定作业卡

A. 冻结条件：记录机器人型号、软件版本、工具型号、负载、安装方式、温度、坐标系定义和操作者；否则前后数据无法比较。
B. 先做重复性：从相同路径多次回到同一参考点，记录散布；不要先拿一次命中判断绝对精度。
C. 做 TCP 多姿态同点：姿态要覆盖多个方向，记录每次关节状态与测量残差；离群点要有原因，不要静默删除。
D. 标定 workpiece_frame：根据夹具/探针/视觉的明确基准建立，而不是靠示教一个“差不多”的原点。
E. 独立验证：用未参与拟合的点和姿态检查残差；如果只用原始采样点验证，会掩盖过拟合和记录错误。
F. 版本化：保存 TCP、base、工件坐标和误差报告；更换工具、夹具或维修后必须重新确认影响范围。
本篇完成判据：你能沿 base → flange → tool0/TCP → workpiece 说清每个坐标变换的来源；能区分重复精度、绝对精度与测量噪声；并能针对“偏了 3 mm”提出先测哪个 frame/参数，而不是立刻改 IK 或手调每个点。
