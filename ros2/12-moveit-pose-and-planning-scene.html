ROS 2 工程实战 12：MoveIt 位姿规划与碰撞场景

这一篇的产物不是“机械臂动了一下”，而是一条你能审查的无碰撞候选路径：它从哪个当前状态出发、要让哪个 TCP 达到什么位姿、避开哪些物体、为什么可以或不可以执行。

先把整个请求链看成五个可检查节点

当前 robot state→目标 Pose / constraints→IK 候选→碰撞 + 路径搜索→trajectory（计划结果）

MoveIt 不是替代 IK 的按钮。它会在目标求解、约束、碰撞场景与路径搜索之间协调。规划成功表示“找到一条在当前模型和场景下合法的路径”；不等于已经发给硬件执行。真实/假硬件执行会在 ROS2-13 进入控制器层。

1. 四个对象的关系：先别把它们都叫“目标”

对象它是什么本篇里怎样验证
Robot State此刻每个关节的位置；规划的起点从 joint states/当前状态取，不凭空假设 home
Pose Goaltool0 在某个 frame 下的位置 + 朝向容差检查目标 frame、TCP link、单位、姿态四元数
Planning Scene机器人、工位几何、允许/禁止碰撞规则的快照RViz 中看到桌、箱体、围栏；碰撞查询有依据
RobotTrajectory关节位置随时间的序列在 RViz DisplayTrajectory 里预览，再决定是否执行
最常见的语义错误：把目标写成“世界坐标的 x/y/z”，但没说明 TCP、参考 frame 与姿态；或者从 RViz 拖动 marker 看到一条动画，就以为已经安全执行。前者目标不完整，后者只是可视化预览。

2. 用 RViz 做第一轮：每次只增加一个变量

第一轮：没有障碍物

  1. 选择正确的 Planning Group；
  2. 确认 End Effector Link 为 tool0；
  3. 设一个附近的 Pose Goal；
  4. Plan，查看成功/失败与轨迹；
  5. 只在 fake hardware 下才允许 Execute。

这一轮只验证模型、IK 和规划管线连通。

第二轮：加入一个桌面 box

  1. 以 base_link 为参考添加 box；
  2. 让直觉上的“直达”路径穿过它；
  3. 重新 Plan，观察路径绕开或报告无解；
  4. 移动/移除 box 后再 Plan，对比结果。

这一轮验证 Planning Scene 真正参与了规划。

3. 从程序视角理解：Plan 和 Execute 是两道闸

# 伪代码：方法名随 MoveItPy / MoveItCpp API 版本略有不同，语义不变。
arm.set_start_state_to_current_state()       # 起点来自当前关节状态
arm.set_pose_target(target_pose, "tool0")   # target_pose.header.frame_id 必须明确

plan = arm.plan()                            # 只计算，不驱动电机
if not plan.success:
    report(plan.error_code)                  # 不要盲目重试；查可达性/碰撞/约束
preview_in_rviz(plan.trajectory)

# 仅确认场景、起点没有变化，并且当前是 fake/授权硬件时：
# arm.execute(plan.trajectory)               # ROS2-13 再接入执行层

MoveItPy 与 MoveItCpp

MoveItPy 是 Python 接口；MoveItCpp 是 C++ 接口。两者都在调用 MoveIt 的规划能力，差别是宿主语言/API，并非一套“Python MoveItCpp”。本阶段先选一种跟通，不混写。

失败要能归类

  • IK 不可达：目标姿态/位置超出工作空间；
  • 碰撞：目标或路径进入了场景物体；
  • 约束过紧：容差几乎不允许任何解；
  • 起点不新鲜：真实 joint state 与规划起点不一致；
  • 超时：搜索空间或规划参数需要调整。

4. 直线 Cartesian Path 不是“Pose Goal 自动直线”

普通 Pose planning 的目标是“到达”，关节空间路径不承诺 TCP 在笛卡尔空间走直线。若工艺要求直线，需要给一串笛卡尔 waypoints，再要求 MoveIt 按小步长求解。

waypoints = [start_pose, pose_at_25_percent, pose_at_50_percent,
             pose_at_75_percent, target_pose]
trajectory, fraction = arm.compute_cartesian_path(
    waypoints, eef_step=0.005, jump_threshold=...)

if fraction < 1.0:
    # 这不是“差一点就无所谓”：说明只有前 fraction 段被成功计算。
    # 禁止把未完成轨迹当成完整工艺路径执行。
    inspect_joint_limit_collision_or_singularity()
本篇验收：你能在 RViz 中创建一个明确 frame 下的 tool0 Pose 目标；对同一个目标分别在“无障碍/有桌面障碍”场景中规划；并能说清普通规划的到达路径与 Cartesian path 的直线要求不是同一件事。下一篇才把已批准的轨迹交给 ros2_control 执行并监测结果。
