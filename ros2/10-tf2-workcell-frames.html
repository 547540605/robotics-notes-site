ROS 2 工程实战 10：TF2 工位坐标

相机、治具、上位机和机械臂各自在不同坐标系说话。TF2 的工作不是“给点加个偏移”，而是让每个点先说明自己在哪张坐标纸上。

工程痛点：同样是 (0.2, 0.1, 0.3)，可能是完全不同的位置

一个视觉节点说“目标在 camera 下 (0.2,0.1,0.3)”，若直接把这三个数送给 ROS2-04 的 IK，就等于假设 camera == base_link。现实中相机安装位置、治具偏置、工位移动都会让这个假设立即失效。

1. 先画帧树，再写一行 IK

world └── workcell # 工位在车间中的位置 ├── base_link # 机械臂基座；IK 的唯一输入坐标系 │ └── ... └── tool0 # robot_state_publisher 动态给出 └── camera # 相机安装位姿 └── target # 感知或任务节点发布的目标
本篇唯一接口契约：无论目标最初来自相机、治具还是上位机，进入 3R IK 前必须成为 base_link 下的点。IK 函数本身不应该知道 camera 或 workcell 的存在。

2. 静态帧与动态帧不能混

静态变换

workcell→base_link、workcell→camera 是安装/标定结果。设备不移动时用 static transform 发布，更新意味着重新标定或重新安装。

动态变换

base_link→tool0 随关节状态变化；camera→target 随目标检测或工件流转变化。它们必须带时间戳。

3. 正确查询：请求 “base_link ← target”

from tf2_ros import Buffer, TransformListener, TransformException
from tf2_geometry_msgs import do_transform_point

# lookup_transform(target_frame, source_frame, time)
# 读作：把 source_frame 中的量转换到 target_frame 中
try:
    tf_base_from_target = tf_buffer.lookup_transform(
        'base_link', 'target', rclpy.time.Time(), timeout=Duration(seconds=0.1))
    point_in_base = do_transform_point(point_in_target, tf_base_from_target)
except TransformException as exc:
    # 本周期禁止调用 IK，也禁止发布新运动目标
    self.get_logger().warn(f'No usable base_link <- target transform: {exc}')
    return

candidates = solve_position_ik(point_in_base.point.x,
                               point_in_base.point.y,
                               point_in_base.point.z)
箭头读法：base_link ← target 不是“target 朝 base_link 运动”，而是“把 target 坐标纸上的量改写到 base_link 坐标纸”。名字读反是 TF2 最常见的错误之一。

4. 实际排查顺序

现象先检查正确动作
lookup 报不存在帧名拼写、发布节点是否启动、树是否连通用 tf2_echo base_link target 验证；不要伪造单位变换。
lookup 超时动态 target 的时间戳、发布频率、仿真时间等待最新有效帧或停止动作；不要使用过期坐标。
末端总是偏同一个量camera/base 安装外参、TCP 偏置、单位回查标定与静态变换，而不是在 IK 中加补丁。
方向整体反了查询的 target/source 顺序、四元数、坐标轴约定在 RViz 开启 TF Axes 与 Marker 同时看。

5. 本篇与后续六轴的关系

六轴、MoveIt、视觉和力控会越来越复杂，但 TF2 契约不变：规划请求必须说清参考坐标系；TCP、相机、工位、工件都必须在同一棵树上。MoveIt 解决“怎样从当前姿态到目标 Pose”，不替你猜目标 Pose 原来属于哪个 frame。
