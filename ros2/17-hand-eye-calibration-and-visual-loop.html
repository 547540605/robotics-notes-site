ROS 2 工程实战 17：手眼标定与视觉闭环

相机看到的是 camera frame 下的目标；机械臂需要的是 base_link 下、针对 TCP 的可执行位姿。中间少任何一个坐标变换，或使用了过期数据，都会让“识别正确”变成“执行偏离”。

视觉闭环的最小真相：识别不等于定位，定位不等于执行

图像→相机内参 + 检测→T_camera_target→手眼 TF 链→T_base_target→工艺偏移→T_base_TCP_goal

每个箭头都要能说明：输入是什么、在哪个 frame、对应哪个时间、失败时怎么拒绝执行。不要把一个检测框中心直接当成机器人 x/y/z。

1. 两种相机安装，TF 链完全不同

Eye-to-hand：相机固定在工位

base_link→camera_link→camera_optical_frame→target

相机相对 base 是固定外参。适合看固定工装、来料、工作台；机械臂运动不改变相机外参。

Eye-in-hand：相机固定在末端

base_link→… joints …→tool0→camera_link→target

相机随手腕运动；tool0 → camera 是固定外参，但 base → camera 每一时刻都来自关节状态和 TF。

光学坐标系的坑：常见 ROS 约定中，camera optical frame 的轴是右、下、前；机器人 base/tool 常按前、左、上理解。不要凭直觉把图像像素的“向右/向下”直接加到机械臂 X/Y。必须依靠发布出来的 frame 和变换验证。

2. 手眼标定在解的不是“相机能否看清”，而是固定外参

相机内参解决“像素如何变成相机光线/三维观测”；手眼标定解决“相机坐标系如何刚性连接到机器人链”。采集多组姿态时，机器人运动与相机观测共同约束一个未知刚体变换，常写成：

Aᵢ X = X Bᵢ
Aᵢ：机器人在两次采样间的相对运动；Bᵢ：相机对标靶观测的相对运动；X：待求的手眼固定变换。

采样为什么必须“多姿态、多方向”

若每次都只沿同一条直线移动，或只绕同一轴小角度旋转，方程对某些方向缺乏约束。要让平移与多个旋转轴都出现明显变化，采样才有辨识力。

标靶为什么必须有尺寸和内参

检测到角点不等于知道标靶相对相机的公制 Pose。标靶尺寸、相机内参和畸变模型共同决定 T_camera_target 的尺度与可靠性。

3. 从视觉目标到 TCP 目标：公式应能逐段指认

# 例：eye-to-hand，视觉系统给出 T_camera_target
T_base_target = T_base_camera · T_camera_target
T_base_tcp_goal = T_base_target · T_target_tcp_goal

# 例：eye-in-hand，base→tool0 来自此刻 joint state / TF
T_base_target = T_base_tool0(now) · T_tool0_camera · T_camera_target
T_base_tcp_goal = T_base_target · T_target_tcp_goal

# T_target_tcp_goal 是“工艺偏移”：例如目标表面上方 50 mm 的预接近姿态。
# 它必须由任务定义，不能把相机看到的 target 原点直接当 TCP 接触点。

先用 TF2 把每段变换查出来、画出来，再将最终 Pose 交给 ROS2-12 的 MoveIt 规划。视觉节点不该直接绕过规划场景，向控制器下关节命令。

4. 时间同步：空间变换正确，时间错了仍然会打偏

场景错误做法正确处理
固定相机、静止工件忽略时间戳也许暂时看不出问题仍保留时间戳和 transform lookup 规则，为运动工件留接口
眼在手上，相机/机械臂运动用“当前” base→tool0 配对一帧较早图像以图像 header.stamp 查询同一时刻的 TF；查不到就拒绝该帧或同步缓存
目标在运动识别一次后直接执行很长轨迹估计延迟与目标速度；必要时 Servo 小步闭环或重新观测再规划

5. 跟做顺序：先做可解释的离线闭环，再讨论“视觉伺服”

A. 不接相机也先搭 TF：用一个已知 static transform 伪造 camera_link，确认 RViz 中 base、tool、camera 三套轴方向正确。
B. 注入一个合成 T_camera_target：通过 TF2 算出 T_base_target，用 marker 同时画出 target 在 camera 与 base 下的位置，检查数值与方向。
C. 加工艺偏移：让目标上方预接近点和最终作业点是两个明确 Pose；先规划到预接近点，再进入小范围动作。
D. 接真实相机前先做内参：检查 CameraInfo、分辨率、畸变模型和标靶实际尺寸；不满足就不采手眼数据。
E. 采手眼数据：记录每一组机器人状态、图像时间戳、标靶检测质量和结果残差；覆盖多方向姿态。
F. 留出独立验证集：用未参与标定的姿态/目标点验证 base 下残差；只复现采样点不算验证。

6. 典型失败现象如何回溯

所有目标整体旋转/平移偏

优先查 camera→base 外参、标靶尺寸单位、camera optical frame 方向，而不是 MoveIt IK。

机械臂一动，视觉目标就漂

优先查 eye-in-hand 是否把动态 base→tool0 用在正确时间戳；检查 tool→camera 固定关节是否定义正确。

不同视角误差差异很大

查相机内参、畸变、标靶检测质量、手眼样本姿态覆盖和 TCP 标定；这通常不是一个常量 xyz 能补掉的。

偶尔很好、偶尔完全错

查消息时间、检测置信度、目标 ID、TF lookup 是否用了最新可用而不是匹配时间；为低置信度设置拒绝条件。

视觉闭环不等于“相机一看就动”。任何将视觉 Pose 交给规划/Servo 的通路都应至少有：目标身份、置信度/残差、时间有效性、工作空间/碰撞检查、预接近策略与停止条件。真机上还必须处于经过批准的速度和安全策略下。
