ROS 2 工程实战 07：RViz 轨迹 Marker

让“目标设计的路径”和“由关节角 FK 回代得到的实际路径”同时可见。没有这层可视化，机械臂看起来在动，并不证明它走对了。

工程痛点：一条线至少有三种完全不同的含义

蓝色目标线表示任务要求的 P(t)；绿色实际线表示把本帧关节角重新做 FK 得到的位置；粉色点表示当前末端。三者必须在同一个 frame下绘制，否则“重合”没有任何意义。

1. Marker 的三个硬规则

坐标系固定

所有轨迹 Marker 都写 header.frame_id='base_link'。不要把目标线画在 camera、实际线画在 base_link 后再拿视觉位置比较。

一条线，一个持续 Marker

使用 LINE_STRIP 持续更新同一 namespace/id 的 points。不要每 20 ms 新建一个 Marker，否则 RViz 和网络都会被历史消息淹没。

点列限长

运行越久，points 越多。设置最大长度；超过时丢弃最早点，或者每个任务段开始时清空并发布 DELETE。

实际点来自 FK

绿色线不能直接复用目标点。它必须来自 selected q 的 FK，否则永远“完美重合”，失去诊断价值。

2. 最小发布器：目标线与实际线分开维护

from visualization_msgs.msg import Marker
from geometry_msgs.msg import Point

def make_line(frame_id, namespace, marker_id, color):
    m = Marker()
    m.header.frame_id = frame_id
    m.ns, m.id = namespace, marker_id
    m.type, m.action = Marker.LINE_STRIP, Marker.ADD
    m.scale.x = 0.008
    m.color.r, m.color.g, m.color.b, m.color.a = *color, 1.0
    return m

target_line = make_line('base_link', 'trajectory', 0, (0.2, 0.75, 1.0))
actual_line = make_line('base_link', 'trajectory', 1, (0.2, 0.9, 0.6))

def append_frame(target_xyz, selected_q):
    actual_xyz = forward_position(*selected_q)  # 不能用 target 替代
    target_line.points.append(Point(x=target_xyz[0], y=target_xyz[1], z=target_xyz[2]))
    actual_line.points.append(Point(x=actual_xyz[0], y=actual_xyz[1], z=actual_xyz[2]))
    del target_line.points[:-MAX_POINTS]
    del actual_line.points[:-MAX_POINTS]
    marker_pub.publish(target_line)
    marker_pub.publish(actual_line)

3. 再画正方形：先固定“在哪个平面”

“画正方形”不是一句充分的任务定义。必须给出四个在 base_link 下的顶点，以及它所在的平面，例如固定 z=0.65 的水平平面，或固定 y 的竖直平面。四条边各复用 ROS2-06 的 A→B 直线生成器；每段开始前都进行完整 IK 预扫描。

如果正方形只在 Marker 中出现，不代表机械臂实际走了它。只有绿色 FK 轨迹闭合且贴近蓝色目标边，才说明关节目标与轨迹链路正确。

4. 看图排错

图上现象优先怀疑
两条线整体平移或旋转frame_id 不一致，或目标并非 base_link 下坐标。
目标线直、实际线弯误用了关节插补，或逐点 IK/FK 约定不一致。
线越来越卡没有限制 points 长度，或不断创建新 Marker。
实际线中断某一帧无可执行 IK；应停下并报告该目标点，不应静默跳过。

本篇结束时，你能用 RViz 证明什么？

  • 目标轨迹、实际 FK 轨迹、当前点属于不同证据，必须同时存在。
