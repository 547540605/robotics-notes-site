动力学进度 · 31a：单连杆 F、N · 31b：RNEA 双向递推

笔记 31b：从末端回收负担，递归得到每个关节力矩

31a 已经算出“每根连杆自己为了加速而需要的惯性力 Fᵢ 与惯性矩 Nᵢ”。但关节 1 还要承担后面所有连杆和工具的负担。RNEA 的核心价值，就是用两遍线性递推把这件事算出来，而不是为每一种连杆数手推一套巨型方程。

本篇地图：外推知道“每根杆怎样动”，内推知道“上游要扛多少”

外推 0→n：把基座运动、关节速度/加速度逐节传到末端，得到每节 ωᵢ, ω̇ᵢ, aᵢ, a_Cᵢ。
局部动力学：31a 用 a_Cᵢ, ωᵢ, ω̇ᵢ 算 Fᵢ,Nᵢ。
内推 n→1：末端负载和下游连杆的力/力矩逐节旋转、平移回父连杆，叠加本节 Fᵢ,Nᵢ。
轴投影：每节总力矩沿该关节转轴的分量，才是标量电机力矩 τᵢ。

1. 两遍方向不能混：它们在传的不是同一种东西

方向递推的量直觉若漏掉会怎样
外推ω, ω̇, a, a_C上游一动，下游必须跟着继承基底运动会把下游当成凭空静止，质心力从源头就错
内推f, n下游越重/越快，上游关节越需要承担它每个关节只算到自己的负担，基座力矩严重偏小
轴投影τ转动关节只由绕自身轴的力矩分量驱动把三维力矩长度误当电机扭矩，方向信息丢失

2. 外推：先让所有量在同一个连杆坐标系里说话

不同教材对旋转矩阵上标/下标有不同书写。本页采用一个统一读法：凡是在连杆 {i} 内相加的向量，先把来自 {i-1} 的量旋转到 {i}。实现时必须与 URDF 的关节轴、零位和坐标变换保持同一约定。

ωᵢ = Rᵢ←ᵢ₋₁ · ωᵢ₋₁ + q̇ᵢ ẑᵢ
ω̇ᵢ = Rᵢ←ᵢ₋₁ · ω̇ᵢ₋₁ + (Rᵢ←ᵢ₋₁ωᵢ₋₁) × (q̇ᵢ ẑᵢ) + q̈ᵢ ẑᵢ
a_Cᵢ = aᵢ + ω̇ᵢ × P_Cᵢ + ωᵢ × (ωᵢ × P_Cᵢ)

三个项分别是什么

  • aᵢ：关节/连杆原点从上游继承来的线加速度；
  • ω̇ᵢ×P_Cᵢ：角加速度带来的切向加速度；
  • ωᵢ×(ωᵢ×P_Cᵢ)：旋转指向中心的向心加速度。

不要遗漏的平动基底

若底座本身升降或移动，a₀ 会一路传到 aᵢ 和 a_Cᵢ。这就是 29/30 中“平面旋转分量 + 垂直平动分量”必须先合成的原因。

符号边界：上面只展示递推骨架。完整 Craig 形式还会包含父到子原点位移 Pᵢ 的传递项；不要从这三行示意式直接删掉原书中的位移/旋转项。写代码时应以经过验证的坐标约定和完整公式为准。

3. 内推：每根杆把“自己 + 下游”一起交给上游

从末端设置边界条件开始。无工具外载荷的理想教学例子可取 fₙ₊₁=0,nₙ₊₁=0；若存在工具、抓取物或外力，就必须以明确 frame 和符号约定给出末端 wrench，不能默认归零。

fᵢ = Rᵢ←ᵢ₊₁ · fᵢ₊₁ + Fᵢ
nᵢ = Nᵢ + Rᵢ←ᵢ₊₁ · nᵢ₊₁ + P_Cᵢ × Fᵢ + Pᵢ₊₁ × (Rᵢ←ᵢ₊₁ · fᵢ₊₁)
项来自哪里物理读法
Nᵢ31a 的欧拉方程本连杆自身转动所需惯性矩
R·nᵢ₊₁下游传回的力矩末端或后续连杆的旋转负担，先转到当前 frame
P_Cᵢ×Fᵢ本连杆质心力质心力相对关节原点的力臂矩
Pᵢ₊₁×(R·fᵢ₊₁)下游传回的力下游力作用在距离当前原点一段距离处，因此额外形成力臂矩
一句话：fᵢ 是“下游合力 + 本节惯性力”；nᵢ 是“下游合力矩 + 本节自转惯性矩 + 两类力臂矩”。这四份来源正是后续 31d 要分别拆开的对象。

4. 最后一步：三维合力矩如何变成一个关节电机扭矩？

转动关节无法直接“执行一个三维力矩向量”；它只能沿自己的转轴施加标量扭矩。因此取内推总力矩在轴上的投影：

τᵢ = nᵢᵀ · ẑᵢ

投影不是取长度

|nᵢ| 会丢失方向，并会把垂直于关节轴、实际不能由该电机直接产生的分量也算进去。点乘保留绕轴正负方向与大小。

轴来自模型

ẑᵢ 必须来自当前 DH/Craig 坐标约定或 URDF joint axis。不能把屏幕上“看起来朝上”的方向当作轴向量。

5. 两连杆的可执行思考顺序

# 输入：q, q_dot, q_ddot；每节 m, P_C, I_C；基座运动；末端 wrench
# 输出：tau[1..n]

forward_pass():
  for i = 1..n:
    rotate parent motion quantities into frame {i}
    add joint q_dot[i], q_ddot[i] contributions
    compute origin acceleration and center-of-mass acceleration
    F[i] = m[i] * a_C[i]
    N[i] = I_C[i] * alpha[i] + omega[i] × (I_C[i] * omega[i])

backward_pass():
  set terminal f[n+1], n[n+1] from tool/external wrench
  for i = n..1:
    rotate child f,n into frame {i}
    f[i] = child_force + F[i]
    n[i] = N[i] + child_moment + P_C[i]×F[i] + P_next[i]×child_force
    tau[i] = dot(n[i], joint_axis[i])
计算顺序不是实现细节：如果还没得到小臂的 f₂,n₂ 就先算肩关节 τ₁，肩部必然漏掉小臂与负载。RNEA 之所以是递归，是因为内推的依赖方向无法颠倒。

带走的四个判断

为什么外推和内推都要做旋转矩阵变换？

向量分量依赖表达坐标系。父/子连杆的轴一般不平行，只有先旋转到同一 frame，力、加速度和力矩才可以相加或叉乘。

无末端外力时，是不是下游项都为零？

不是。最末端边界 wrench 可以为零，但末端前一节仍有自身惯性力/惯性矩；它继续内推后，上游关节依旧要承担所有连杆的运动负担。

为什么关节力矩用点乘而不是叉乘？

内推已经得到关于关节原点的总力矩向量。关节要的是该向量沿可转轴的标量分量，所以做点乘投影；叉乘是从力和力臂构造力矩时才使用。

RNEA 给出了力矩，是不是就能直接给真机下 torque？

不能直接跳到真机。还要知道厂商是否允许 torque mode、参数是否辨识、关节/速度/力矩边界、传感器与安全策略。RNEA 首先是模型计算与前馈依据。
