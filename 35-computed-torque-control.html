笔记 35：计算力矩控制——先预估“需要多少力矩”，再用反馈收尾

两连杆高速协同运动时，关节 1 的力矩会受关节 2 姿态、速度、加速度和重力影响。只靠 PID 可以纠错，但它必须等偏差出现后才行动。计算力矩控制（Computed Torque Control, CTC）把已知的动力学模型作为前馈：在误差还没有产生时，先给出大致正确的努力量。

四张笔记在这里第一次闭环

33: (q_d,q̇_d,q̈_d) + 32: M,h,g + 34: 误差 PD → τ_cmd → 两连杆实际状态 (q,q̇)

这不是四套独立公式：33 提供“希望怎么动”，32 说明“这种运动需要承担哪些惯性、耦合和重力”，34 提供“模型不准时如何拉回”。

1. 从两连杆动力学式开始，而不是背一条新控制律

M(q)q̈ + h(q,q̇) + g(q) = τ
动力学量32 中的意义CTC 怎么用
M(q)构型相关的惯性矩阵把“希望的虚拟加速度”换算成对应力矩。
h(q,q̇)速度耦合项（常写作 C(q,q̇)q̇）提前抵消运动中可预测的耦合负担。
g(q)重力矩提前托住当前姿态的负载，而不是等它下垂后用误差拉回。
q_d,q̇_d,q̈_d33 的连续参考轨迹定义要实现的运动，而不只是终点位置。

2. CTC 控制律：模型前馈 + 误差反馈

取 e=q_d-q 与 ė=q̇_d-q̇，先构造一个虚拟加速度：

v = q̈_d + K_d ė + K_p e

再通过模型把它转换成关节力矩：

τ_CTC = M̂(q)v + ĥ(q,q̇) + ĝ(q)

模型完全正确时，发生什么？

若 M̂=M, ĥ=h, ĝ=g，代回真实动力学式可得：

ë + K_d ė + K_p e = 0

原本互相耦合的非线性二连杆，误差动力学被近似整理成两个可按二阶系统理解的闭环通道。

帽子（^）为什么不能省略？

控制器手中的是估计模型，不是上帝视角。负载变化、摩擦、装配误差和柔性都会造成 M̂,ĥ,ĝ 与真实对象不同；所以 CTC 必须保留反馈和全部限幅，不能把前馈当成安全保证。

3. 纯 PD 与 CTC 的分工差异

纯 PD

τ_PD = K_p e + K_d ė

不显式知道重力和耦合。遇到未知扰动也能靠偏差纠正，但通常要允许更大误差或更激进的增益，才换来同等的跟踪。

CTC

τ_CTC = 前馈(M̂,ĥ,ĝ) + M̂(K_pe+K_dė)

用模型处理可预测部分，用 PD 处理模型残差。优势不是“永远精确”，而是让反馈不必独自扛全部动力学负担。

别混淆：CTC 中的 M̂(q) 不只乘 q̈_d；它还乘反馈生成的 K_d ė+K_p e。若只写 M̂q̈_d+ĥ+ĝ+K_pe+K_dė，量纲虽可拼出来，但反馈增益与不同姿态惯量之间的关系已被改变。

5. 工程上必须补齐的四个边界

  1. 单位和坐标：q 用 rad、q̈ 用 rad/s²、τ 用 N·m；关节正方向、重力方向与动力学模型一致才能谈前馈。
  2. 力矩/速度/位置限幅：CTC 可能在起步或模型突变时索要过大的力矩；输出必须过限幅、速率限制和硬件安全链。
  3. 辨识与负载更新：更换夹具或工件后，质量、质心、惯量都应作为模型参数更新，而不是只把 PID 增益调大。
  4. 控制频率和延迟：模型项、状态反馈与轨迹采样必须在统一时间语义下工作；过时状态会把前馈变成错时的扰动。
CTC 是否等于“逆动力学”？

逆动力学是“给定状态与期望加速度，求所需力矩”的计算；CTC 使用该计算构成一个闭环控制器，并加上误差反馈。前者是模型运算，后者是控制架构。

为什么 CTC 还用实际 q、q̇，而不是全用参考 q_d、q̇_d？

这是常见实现选择之一：用实际状态计算模型项可更贴近当前对象，但仍受噪声和模型误差影响。也有按期望状态计算的前馈变体。无论选哪种，都要明确使用的状态、时间戳和误差反馈如何闭环。

能把这个仿真结论直接推广到真实六轴吗？

不能。六轴还涉及完整惯量参数、传动柔性、摩擦、驱动器内部环、采样/通信延迟和安全策略。这里证明的是公式连接关系与模型失配趋势；真实接入必须先在厂商控制接口和安全边界内逐级验证。
